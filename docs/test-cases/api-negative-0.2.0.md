# Расширенное негативное тестирование API FleetControl 0.2.0

## Назначение документа

Документ фиксирует результаты расширенного негативного тестирования API
выпущенной версии FleetControl 0.2.0 перед подготовкой версии 1.0.0.

Обнаруженные отклонения от ожидаемого поведения должны регистрироваться
отдельными задачами типа `Bug`.

Тестируемый endpoint:

`POST /replacement-assignments`

Версия: `0.2.0`

---

## NT-001. Строковое значение vehicle_id

### Запрос

```json
{
  "driver_id": 1,
  "vehicle_id": "abc"
}
```

### Ожидаемый результат

- HTTP `400 Bad Request`;
- клиент получает сообщение о некорректном идентификаторе;
- назначение не создаётся;
- сервер не возвращает внутреннюю ошибку.

### Фактический результат

Получен HTTP `500 Internal Server Error` вместо ожидаемого
`400 Bad Request`.

PostgreSQL вернул ошибку `22P02`:
`invalid input syntax for type bigint: "abc"`.

Дефект зарегистрирован в Jira: `FLEET-33`.

### Статус

`FAIL`

## NT-008. Назначение автомобиля неактивному водителю

### Предусловия

- водитель с `id = 3` существует;
- его статус — `INACTIVE`;
- автомобиль с `id = 1` существует и имеет статус `AVAILABLE`.

### Запрос

```json
{
  "driver_id": 3,
  "vehicle_id": 1
}
```

### Ожидаемый результат

Неактивному водителю не должно создаваться новое рабочее назначение.
API должен отклонить запрос с клиентской ошибкой.

### Фактический результат

Получен HTTP `201 Created`.

Для водителя с `id = 3` и статусом `INACTIVE` успешно создано
назначение автомобиля с `id = 1`.

API не проверяет статус водителя перед созданием назначения.

Дефект зарегистрирован в Jira: `FLEET-34`.

### Статус

`FAIL`
