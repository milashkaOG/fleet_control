# Ручное тестирование назначения подменного автомобиля

## Назначение документа

Документ содержит ручные тест-кейсы для проверки функции назначения подменного автомобиля водителю в рамках пользовательской истории FLEET-12.

Тестируемый endpoint:

`POST /replacement-assignments`

Версия: `0.2.0`

---

## TC-RA-001. Успешное назначение доступного автомобиля

### Предусловия

- приложение FleetControl запущено;
- PostgreSQL доступен;
- водитель с `id = 1` существует;
- автомобиль с `id = 3` существует;
- автомобиль имеет статус `AVAILABLE`;
- активного назначения для автомобиля нет.

### Шаги

1. Отправить POST-запрос на `/replacement-assignments`.
2. Передать:

```json
{
  "driver_id": 1,
  "vehicle_id": 3
}
```

3. Проверить HTTP-ответ.
4. Проверить таблицу `replacement_vehicle_assignments`.
5. Проверить состояние автомобиля в таблице `vehicles`.

### Ожидаемый результат

- HTTP `201 Created`;
- создано новое назначение;
- назначение содержит правильные `driver_id` и `vehicle_id`;
- зафиксирована дата начала назначения;
- статус автомобиля изменён с `AVAILABLE` на `IN_USE`.

### Фактический результат

Получен HTTP 201 Created. Запись назначения создана.
Статус автомобиля с id = 3 изменён с AVAILABLE на IN_USE.

### Статус

`PASS`

## TC-RA-002. Повторное назначение уже используемого автомобиля

### Предусловия

- водитель с `id = 2` существует;
- автомобиль с `id = 3` уже назначен другому водителю;
- автомобиль с `id = 3` имеет статус `IN_USE`.

### Шаги

1. Отправить POST-запрос на `/replacement-assignments`.
2. Передать:

```json
{
  "driver_id": 2,
  "vehicle_id": 3
}
```

3. Проверить HTTP-ответ.
4. Проверить таблицу `replacement_vehicle_assignments`.

### Ожидаемый результат

- HTTP `409 Conflict`;
- возвращается сообщение `Vehicle is not available`;
- второе назначение для автомобиля не создаётся.

### Фактический результат

Получен HTTP 409 Conflict с сообщением `Vehicle is not available`.
Повторное назначение автомобиля с `id = 3` не создано.

### Статус

`PASS`

## TC-RA-003. Назначение автомобиля, находящегося в ремонте

- водитель с `id = 1` существует;
- автомобиль с `id = 2` существует;

2. Передать:

```json
{
  "driver_id": 1,
```

### Фактический результат

Получен HTTP 409 Conflict с сообщением `Vehicle is not available`.
Назначение автомобиля с `id = 2` не создано. Статус автомобиля
остался `REPAIR`.

### Статус

`PASS`

## TC-RA-005. Назначение несуществующему водителю

### Предусловия

- водителя с `id = 999` не существует;
- автомобиль с `id = 1` существует;
- автомобиль имеет статус `AVAILABLE`.

### Шаги

1. Отправить POST-запрос на `/replacement-assignments`.
2. Передать:

```json
{
  "driver_id": 999,
  "vehicle_id": 1
}
```

3. Проверить HTTP-ответ.
4. Проверить состояние автомобиля с `id = 1`.

### Ожидаемый результат

- HTTP `400 Bad Request`;
- назначение не создаётся;
- транзакция откатывается;
- автомобиль остаётся в статусе `AVAILABLE`.

### Фактический результат

Получен HTTP 400 Bad Request с сообщением `Driver or vehicle does not exist`.
Назначение для несуществующего водителя не создано. Транзакция откатилась,
автомобиль с `id = 1` сохранил статус `AVAILABLE`.

### Статус

`PASS`

## TC-RA-006. Отсутствует обязательный параметр

### Предусловия

- приложение FleetControl запущено.

### Шаги

1. Отправить POST-запрос на `/replacement-assignments`.
2. Передать только `driver_id`:

```json
{
  "driver_id": 1
}
```

3. Проверить HTTP-ответ.

### Ожидаемый результат

- HTTP `400 Bad Request`;
- возвращается сообщение `driver_id and vehicle_id are required`;
- назначение не создаётся.

### Фактический результат

Получен HTTP 400 Bad Request с сообщением
`driver_id and vehicle_id are required`.
Назначение не создано.

### Статус

`PASS`
